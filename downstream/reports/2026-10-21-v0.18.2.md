## Automated checks

- Portable patch replay against clean upstream, verified against feature-file hashes.
- 199 backend tests across 11 modules, plus generated API contract verification.
- One pre-existing expected failure documents filesystem orphan cleanup without a database row.
- TypeScript production build and six desktop/mobile Playwright regressions passed.
- The release bench now also gates all application/migration Python lint and
  formatting, frontend lint, E2E lint and i18n extraction. Opening the review PR
  exposed inherited dual-stream formatting debt and a missing mobile test tag;
  those were corrected without changing runtime behavior.
- Deployment Compose rendering passed in `docker:28.5.1-cli`, ARM64, offline, exit 0.

Backend tests ran in disposable AMD64 containers using the matching upstream
ROCm image, no network, no GPU, and temporary config/media directories. Browser
tests used `mcr.microsoft.com/playwright:v1.59.1-noble` and the matching Playwright
package. Local browser checks ran on ARM64; GitHub checks ran on AMD64.

## Deployment and recovery notes

Portainer stack 72 was updated with the image pinned by digest. Its environment,
camera streams, devices and storage paths were preserved. The previous
image was `ghcr.io/icn-brendon/frigate:ac06ebee-rocm`.

A consistent SQLite backup and config copy are retained at:

`/tank/apps/frigate/config/upgrade-backups/20261021T013033Z/`

The old Portainer container had failed to start five days earlier. Starting the
existing container restored the deployment path. Portainer's anonymous registry
pull was denied, so the authenticated NAS pre-pulled the exact candidate and the
stack now uses `pull_policy: if_not_present`.

The first AMD model compilation took about two minutes. Initial API readiness
errors and recording-cache warnings occurred during startup. After compilation,
both cameras reached 5 FPS and the final log observation had no repeated detector,
FFmpeg or recording-backlog errors. An upstream nginx warning about an
uninitialized `go2rtc_stream_proxy` variable was observed on some API requests.
It did not prevent the tested API/media/export operations.

## Home Assistant relay acceptance

Replacing Frigate left the relay attached to the old network namespace. It was
recreated with the existing specification against the new Frigate container.
The stopped old relay descriptor was removed after verification.

Native go2rtc and the relay also competed for UDP 8555. The persistent Frigate
config now puts native WebRTC on 18555, advertising `10.0.0.70:18555`, while the
relay keeps 8555. RTSP 8554 and the API ports are unchanged. The config backup is
`/tank/apps/frigate/config/config.yml.before-webrtc-ports-20261021T021834Z`.

All four adapter streams received and decoded real H.264 frames:

| Stream | Resolution | Pixel standard deviation |
| --- | --- | --- |
| Front_Gate | 896 x 512 | 55.53 |
| Front_Driveway | 896 x 512 | 77.50 |
| Front_Gate_HD | 2256 x 1256 | 63.58 |
| Front_Driveway_HD | 2256 x 1256 | 77.02 |

The isolated ARM64 client used Python 3.13.16, aiortc 1.14.0, aiohttp 3.12.15 and
av 16.1.0, built from `Dockerfile.relay-test`, with bridge networking and a
temporary localhost-only signaling tunnel. `live_relay_uat.py` exited 0 and the
container was removed. The default aiortc receive buffer was too small for HD
I-frames; a 4096-packet buffer resolved the test-client limitation. The reusable
`live_relay_uat.py` preserves this setting. No product codec change was needed.

Portainer relay stack 89's stored Git credential failed to fetch the private
repository. Its running stack specification matched the repository, so the
relay was recreated from that specification. The credential still needs repair
before a future automatic Git redeploy can be relied upon.

The final API check after the go2rtc/relay restart also passed. Gate processed
5.0 FPS, Driveway 5.1 FPS, both skipped 0 FPS, AMD inference measured 11.9 ms,
and both qualities had recordings. All three service containers were healthy.

## Coverage limits

Mobile checks simulate an iPhone-sized layout in Chromium. They do not certify
physical iOS/Safari hardware decoding. Recording retention and pre/post-capture
boundaries are covered by automated temporary-file/database tests; no production
recordings were deliberately expired. The orphan-file expected failure remains.
