## Deployment and recovery notes

Portainer stack 72 was updated with the image pinned by digest. Its environment,
camera configuration, devices and storage paths were preserved. The previous
image was `ghcr.io/icn-brendon/frigate:ac06ebee-rocm`.

A consistent SQLite backup and config copy are retained at:

`/tank/apps/frigate/config/upgrade-backups/20261021T013033Z/`

The old Portainer container had failed to start five days earlier. Starting the
existing container restored the deployment path. Portainer's anonymous registry
pull was denied, so the authenticated NAS pre-pulled the exact candidate and the
stack now uses `pull_policy: if_not_present`.

The first AMD model compilation took about two minutes. Initial API readiness
errors and recording-cache warnings occurred during startup. After compilation,
both cameras reached 5 FPS and the final log observation had no repeated detector,
FFmpeg or recording-backlog errors. An upstream nginx warning about an
uninitialized `go2rtc_stream_proxy` variable was observed on some API requests.
It did not prevent the tested API/media/export operations.

## Coverage limits

Mobile checks simulate an iPhone-sized layout in Chromium. They do not certify
physical iOS/Safari hardware decoding. Recording retention and pre/post-capture
boundaries are covered by automated temporary-file/database tests; no production
recordings were deliberately expired. The orphan-file expected failure remains.
